# AGENTS

## Principles
- Clarity and consistency over cleverness. Minimal changes. Match existing patterns.
- Keep components/functions short; break down when it improves structure.
- TypeScript everywhere; no `any` unless isolated and necessary.
- No unnecessary `try/catch`. Avoid casting; use narrowing.
- Named exports only (no default exports, except Next.js pages).
- Absolute imports via `@/` unless same directory.
- Follow existing ESLint setup; don't reformat unrelated code.
- Zod type-only: `import type * as z from 'zod';`.
- Let compiler infer return types unless annotation adds clarity.
- Options object for 3+ params, optional flags, or ambiguous args.
- Hypothesis-driven debugging: 1-3 causes, validate most likely first.

## Token efficiency
- Skip recaps unless the result is ambiguous or you need more input.

## Commands
Only these `npm run` scripts: `build-local`, `lint`, `check:types`, `check:deps`, `check:i18n`, `test`, `test:e2e`.

## Git Commits
Conventional Commits: `type: summary` without scope. The summary should be a short, specific sentence that explains what changed and where or why, not a vague phrase. Types: `feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`. `BREAKING CHANGE:` footer when needed.

## Env
All env vars validated in `Env.ts`; never read `process.env` directly.

## Styling
Tailwind v4 utility classes. Reuse shared components. Responsive. No unnecessary classes.

## React
- No `useMemo`/`useCallback` (React compiler handles it). Avoid `useEffect`.
- Single `props` param with inline type; access as `props.foo` (no destructuring).
- Use `React.ReactNode`, not `ReactNode`.
- Inline short event handlers; extract only when complex.

## Pages
- Default export name ends with `Page`. Props alias (if reused) ends with `PageProps`.
- Locale pages: `props: { params: Promise<{ locale: string }> }` → `await props.params` → `setRequestLocale(locale)`.
- Escape glob chars in shell commands for Next.js paths.
- Dashboard pages (sit behind auth); define meta once in layout, not in each page.

## i18n (next-intl)
- Never hard-code user-visible strings. Page namespaces end with `Page`.
- Server: `getTranslations`; Client: `useTranslations`.
- Context-specific keys (`card_title`, `meta_description`). Use `t.rich(...)` for markup.
- Use sentence case for translations.
- Error messages: short, no "try again" variants.

## SEO
Every page must be indexable, localized, and admin-portal-ready. The SEO data layer is
designed so a future admin/CMS can own the content by swapping one implementation. Full guide
(recipe, checklist, where SEO is/isn't needed): `docs/SEO.md`.
- **Metadata:** every page exports `generateMetadata`, resolves its `meta_title`/
  `meta_description` from i18n, and returns
  `buildPageMetadata({ path, locale, title, description, robots? })` from `@/utils/Seo`.
  Pages never assemble `openGraph`/`twitter`/`canonical`/`alternates` themselves.
- **Admin override seam:** `buildPageMetadata` merges i18n defaults with
  `seoRepository.getOverride({ path, locale })` (`src/libs/seo`). The static source returns no
  overrides today; the future admin portal backs this one interface with the DB so editors can
  override any SEO field without touching pages. Keep `getOverride`/`listRoutes` async.
- **Strings:** define `meta_title` / `meta_description` per namespace in `src/locales`
  (sentence case, no boilerplate copy). One `<h1>` per page.
- **Canonical + hreflang** are produced automatically for every locale; don't hand-roll them.
- **Robots:** auth/dashboard pages pass `robots: { index: false, follow: false }`; also add
  the path to `disallow` in `src/app/robots.ts`.
- **Sitemap:** new routes are registered in `seoRepository.listRoutes()` so `src/app/sitemap.ts`
  picks them up — do not edit the sitemap per route.
- **Structured data:** add JSON-LD for new content types (Article/Product/Breadcrumb) via
  `@/components/seo/JsonLd`, built in `src/libs/seo/StructuredData.ts` from config.
- **Absolute URLs:** always derive from `getBaseUrl()` (reads `NEXT_PUBLIC_APP_URL`); never
  hardcode the domain. Org/brand details live in `AppConfig` / `OrgConfig`.
- **OG image** is generated by `src/app/[locale]/opengraph-image.tsx`; no manual asset needed.

## Admin portal
The admin portal (`src/app/[locale]/(auth)/admin`, components in `src/components/admin`) is an
internal, auth-only CMS. It is **content management, not a public page** — the rules below are
deliberate, not omissions.
- **No SEO on admin pages.** Admin pages and layouts must NOT export `generateMetadata`,
  call `buildPageMetadata`, set robots/canonical/OG/JSON-LD, or appear in the sitemap. Use a
  static `metadata = { title }` at most. `/admin` stays in `robots.ts` `disallow`; access is
  gated in `src/proxy.ts`. SEO is a *thing the admin edits* (marketing-page metadata), never a
  property of the admin pages themselves.
- **Admin edits marketing SEO only.** The SEO that admins manage targets marketing pages via the
  `seoRepository` seam (`src/libs/seo`) — never admin/dashboard routes.
- **No i18n in admin.** Admin is English-only: hardcode user-visible strings, do not use
  `getTranslations`/`useTranslations`, and add no `Admin*` keys to `src/locales`. (`setRequestLocale`
  is still fine — it sets locale context, not translations.) This is the one place the
  "never hard-code user-visible strings" rule does not apply.

## JSDoc
- Start each block with `/**` directly above the symbol.
- Short, sentence-case, present-tense description of intent.
- Order: description → `@param` → `@returns` → `@throws` (only if it can throw).

## Tests
- `*.test.ts` for unit tests; `*.integ.ts` for integration tests; `*.e2e.ts` for Playwright tests.
- `*.test.ts` co-located with implementation; `*.integ.ts` and `*.e2e.ts` in `tests/` directory.
- Top `describe` = subject; nested `describe` to group scenarios or contexts.
- `it` titles: short, third-person present, `verb + object + context`. Sentence case, no period.
- Omit "should/works/handles/checks/validates". State what, not how.
- Avoid mocking unless necessary.
